# 狼人杀练习局（xun extension）

本软件为[xun-agent](https://github.com/menxli/xun)的拓展插件。

在会话里发 `/werewolf`，开一局 **1 个真人（你）+ 其余座位 AI** 的狼人杀：法官用卡片问你要什么板子、坐几号、演谁、规则怎么微调，然后自动天黑；你出局后还能继续问法官、要复盘。

安装方法：
将`werewolf` 文件夹放到 `$XUN_HOME/extensions/`（默认`./.xun/extensions/`）。

**本插件完全由 xun 驱动的 Agent 开发...不保证代码质量与稳定性。**

## 完全由 xun 驱动，没有一行"额外基础设施"

这个 extension 里没有 web 服务、没有前端、没有数据库、不需要 pip 安装。用到的能力全是 xun 的：

| 需要的事 | 用的是 xun 的什么 |
|---|---|
| 让 `/werewolf` 出现在会话里 | extension 发现机制 + `agent.command.register(Command(...))` |
| 卡片问用户选项 | `agent.get_choice(...)` → `ChoiceRequest`（`default` 前端会预选中；法官卡片带 `_skip_auto_confirm=True`，开着自动确认也不替玩家点） |
| 玩家在输入框里发言、问法官 | `before_execution` 钩子填 `ExecutionLoopParams.takeover_result` —— 这次执行由法官回答，**根本不进模型** |
| 法官播报、局面看板、票型、身份牌与终局横幅（内联 SVG） | `InfoEvent` / `HTMLInfoEvent` |
| 每个 AI 座位的记忆、结构化输出、重试 | 每个座位就是一个 xun `Agent`（复盘教练也是） |
| 狼队刀口（每轮）、举手、退水、投票这些「同时决定」 | 一次**并发**发问（守护线程，同时在算的座位最多 6 个），收齐才公布 |
| 聊天流、工作区、取消、收尾 | xun 的 display 与 `Agent` 生命周期（`before_finalize`） |

**本仓库只写了三样东西：游戏规则引擎、给 AI 的提示词与人格、什么时候播什么内容的编排。**

## 装

xun 的 home **不是家目录**：`config.get_home_dir()` 先看环境变量 `XUN_HOME`，没有就用
**启动 xun 时所在目录**下的 `.xun`（`Path.cwd() / ".xun"`）。扩展装在 `$XUN_HOME/extensions/` 里，
package 形态的文件名固定是 `extensions/<名字>/setup_extension.py`。

```bash
XUN_HOME_DIR="${XUN_HOME:-$PWD/.xun}"                 # 在你打算启动 xun 的那个目录里执行
mkdir -p "$XUN_HOME_DIR/extensions"
ln -s "$(pwd)" "$XUN_HOME_DIR/extensions/werewolf"    # 整个仓库就是 extension 目录；改完代码重启 xun 生效
```

或打包后解到 `$XUN_HOME/extensions/`（zip 顶层已经是 `werewolf/`）。
前提：xun 里配好了模型与 key（AI 座位真的会调模型）、**Python 3.12+**（照 xun 的 `requires-python`）。

## 玩

| 命令 | 作用 |
|---|---|
| `/werewolf` | 开一局。法官卡片依次问：板子 → 座位 → 身份 → 规则微调 → 确认 |
| `/werewolf status` | 当前局面（公开信息；你出局后带上帝视角）。也认 `局面` |
| `/werewolf stop` | 终止这一局。法官还在，复盘随时问。也认 `停` |
| `/werewolf ?` | 用法 |

- **警长决定每天往哪个方向发言**（顺时针 / 逆时针）：起点自动是他旁边那位，绕一圈最后才轮到他，
  所以他每天**压轴归票** —— 和你平时线下玩的规则一致（不是「警长想从几号开始就从几号开始」）。
- 轮到你发言时，卡片上写着**你排第几、前面谁已经说过、后面还剩谁**（AI 座位拿到的是同一句话），
  不用自己在脑子里数座位。
- 命令**不带参数**：开局设置一律走卡片，每步第一个选项就是默认值，**一路点下去最快**。
- **一局开始后，这个会话的 agent 就是法官**：它不再调用模型，也不给自己新建 agent 或换工作目录
  （每个 AI 座位有自己那份 agent 与工作目录，那是座位的事，不是法官的）。
  选择题点法官卡片，**发言和遗言直接发在这条会话的输入框里** —— 不用切会话、不用切 agent。
- 你发进这条会话的话不会传给任何玩家；问法官问题也是同一个输入框，它只看公开局面，问身份一律不给。
- **一局一会话，且接管是终身的**：打完之后这条会话固定是法官（复盘随时问），再发 `/werewolf`
  只会得到一句提示。想把这个 agent 拿去干别的 —— 点前端「新建会话」，那是唯一真正把 agent
  交回给你自己的出口，所以我们不提供 `/werewolf leave` 之类的假出口。
- 开局那一刻起，这个 agent 的工具箱与它自带的斜杠命令都收起来：`/tools`、`/clear`、`/config`
  都不再响应，只剩 `/werewolf …` 与 `/auto-say`。要再开一局得点前端「新建会话」。
- 发言字数上限**只是提示**：超了法官照播不误，一个字都不砍（只在复盘里记下谁超时）；只有模型失控刷屏那种长度才截。
- AI 发言的规矩写在静态纪律里（`actors/style.py`）：**一句一个信息点、先结论后理由、说完就交下一位**，并且有一份「首先/综合来看/值得注意的是」这类书面腔的黑名单和一张桌上的黑话表（金水、查杀、警徽流、归票…… 用它们话更短）。每个座位还抽一条**口头习惯**和一档黑话密度，八个人说话不该一个腔。
- 座位性格是一根根分开的轴：抢麦（含爱出风头）、激进/保守、讲逻辑还是靠听感、话长话短、敢不敢把话说死、心软还是冷面、信不信别人跳的身份、**坚持己见还是墙头草**（自己定的票不轻易改 / 风向一变就敢改票，但每次改口都得说一句为什么）。一根轴只管一件事，免得模型同时收到「你得死扛」和「你得从众」这种自相矛盾的指令。性格抽样走的是独立随机流：改人格不会顺手改掉发牌、刀口和票型。
- 夜里狼队出刀是**盲投表决**：每只狼同时投一次（看不见队友这一轮投谁），谁拿到**唯一最高票**就刀谁；
  投不到就复投，轮与轮之间狼队只收到**票型**（`5号 2票、9号 1票`）和队友各自投了谁，没有自由讨论 ——
  跟面杀夜里不许出声、靠比数字统一刀口是同一件事。最多投 3 轮，投不到唯一最高票就**空刀**
  （真实局里这叫分刀，代价本来就是这一夜没人死）。每个狼可以附一句 **14 字以内**的理由，只发给狼队；
  真人狼人卡片上同样有这一栏（点「不说」或自己打一句）。
  这儿以前是「平票就执行编号最小的提议」，400 局 12 人实测：45% 的夜靠它兜底改判，1 号被刀 228 次、
  12 号只有 80 次 —— 狼队自己没谈拢，代价全压在低号位玩家身上。改成表决后各座被刀次数压平到 117–144
  （低/高号位比值 2.07 → 0.93），代价是 8.1% 的夜空刀。每晚投了几轮也单列进复盘，不给截掉。

显示形态自动按 xun 版本选：有 `HTMLInfoEvent` 时是带标题栏的卡片（局面看板、票型带得票条、座位 chips），
旧版自动退回紧凑纯文本，内容一条不少。要固定：`WEREWOLF_UI=text` / `html`。

发身份牌时那张卡是**内联 SVG 横条**（`werewolf/assets/roles/*.svg`，七个角色一人一张，460×72，共 14 KB）：
座位徽章、图标、身份名、技能与阵营排成一行，座位号是图里的占位符，渲染时填进去。做成横条而不是竖版海报是因为这张卡下面还有板子与规则要读，海报会把屏幕整块吃掉。为什么内联而不是 `<img src="assets/...">`——xun 的 web 服务
不服务插件目录（没有静态资源路由），前端根本取不到那个 URL；PNG 想显示只剩 base64 内嵌一条路，
一张几十 KB 还只有一个分辨率。SVG 走前端那道 DOMPurify 清洗是原样通过的（实测 3.4.16，清洗前后
逐字节相同），所以资产里刻意不用 `<style>`/`<use>`/`xlink:href`。纯文本形态不放图像，那张卡由
`╔═╗` 大字框承担（座位、身份、阵营、技能说明一条不少，只是没有图）。横条画过的话（身份、阵营、技能）网页里不再用文字抄一遍；文本形态因为没有图，那条说明必须说全。

终局那张卡顶部还有一条**胜负横幅**（`assets/banners/wolf.svg` / `good.svg`，一局只出现一次），
文本形态退化成一行 `★ 好人阵营胜利 ★`。**平局与中途终止没有横幅** —— 对着一场没打完或者平掉的局
喊「胜利」是撒谎，那种结局就老老实实只报身份。

你打的字在会话流里只有你自己那一条气泡，法官不会再把它播成「5号」的座位气泡（发言托管时
另有一行「已按默认行动托管」，不会静默吞掉）。

你的输入分三种，卡片上也各自写着这一步该怎么回答（猜错的代价是输入被吞，所以宁可写三行）：

| 这一步 | 怎么回答 |
|---|---|
| 选人选动作（投票、夜里行动、举手、警徽、女巫用药） | 弹**带按钮**的卡片，点按钮再点「提交」；这一步在输入框里打字不算回答 |
| 轮到你说话（发言、警上发言、遗言） | 也播一张卡，但那张卡**没有按钮也没有输入框**，只说明轮到谁；话发在会话输入框里 |
| 问法官（局面、规则、复盘） | 同一个输入框，但只在**没轮到你的时候**算提问；轮到你发言时，输入框里的第一条会被当成那句发言 |

想随时查局面用 `/werewolf status` —— 斜杠命令不走 execution loop，任何时刻都不会被当成发言吞掉。
我们不猜你的意图（例如「以法官开头就不当发言」）：猜错的两种代价 —— 吞掉你写好的一句发言，
或者把你随口的问题播给全场 —— 都不可接受，所以规则只留一条：输入框就是当前那件事的答案。

AI 座位在算的时候，侧栏写「运行中」、活动条转圈。法官把这段等待包进 agent 的执行态，
xun 在 ExecutionScope 进出时广播 `AgentRunningStart/EndEvent` —— 新前端的「忙不忙」只认这个。
（旧那条 `ModelWorkingEvent` 圆点在 1.1.1 之后的前端画不出来：活动条的 working 只看 `runningAgents`，
它现在只负责终端里那一行「running」。）招呼开在引擎唯一的提问出口上，所以夜里刀人、投票、举手、退水
这些**并发**环节也一样在亮 —— 先前只有逐个提问的路径会打招呼，一到并发段就整段静默，看着像整局卡死
（`test_parallel` 钉着这条）。

**代价**：前端在运行态下把「发送」换成「停止」，那几秒打不了字（草稿不清空，切回来还能发）。
所以法官只在**没有卡片等你、也没在等你发言**的时候才占执行态，一进真人环节立刻松开。
实测（6 人板真浏览器）：白天连排发言 42 秒次次采样都是「运行中」；卡片挂着的 21 秒全是「等待输入」，
期间草稿照样发得出去。

```bash
python -m werewolf.tests.run          # 187 项 / 11 套件，全部用脚本玩家，不发一次 LLM 请求
WEREWOLF_UI=text python -m werewolf.tests.run      # 同一套再跑一遍纯文本形态
```

看板卡片那几项测试需要 xun 提供 `HTMLInfoEvent`；xun 太旧没这个类时它们会报 `ImportError`，
不是规则坏了（插件本身是探测这个类来决定形态的，缺了就整体退回纯文本，功能一条不少）。

超时兜底：xun 建 OpenAI client 不传 `timeout`（插件改不了它），所以一个座位的请求真能永不返回。
引擎因此给每次提问上计时器（`engine.ASK_TIMEOUT_SEC`，只计 AI 座位）：超时就按默认行动托管那个座位，
局面照走，`/werewolf stop` 也不用陪着等。托管不等于取消 —— 那个请求还在飞，所以我们**不再问这个座位第二次**
（同时问两次会把它的会话写乱），等它自己回来才恢复；真人那一侧的卡片与输入框不计时，多久都等。

长局里 AI 座位的会话交给 xun 的 auto_compact 摘要压缩（阈值取你 xun 配置里的 `auto_compact.token_threshold`）；
插件另外留了一个设在阈值之上的**兜底硬顶**（`LLMActor.keep_pairs=14` 对），只有你把 auto_compact 关掉时才会用到。
再往前的历史靠每轮重算的**前情提要**：`RECAP_EVENTS=24` 条事件，一条发言在提要里留 `_clip=90` 字 ——
这两个数就是玩家「还记得前面谁说过什么」的窗口大小，`test_flow` 钉着下限，别顺手调小。

要改代码，先看 **`AGENTS.md`**。
